# Звіт лабораторної роботи

Звіт пишеться в `labs/labNN/report/report.md` і збирається командою
`uv run mllabs report N` у `labs/labNN/report/Звіт_ЛРN.pdf`.

Оформлення — **автоматичне**, вручну нічого не налаштовуй: титульна сторінка відтворює
`Шаблон_звіту_ПР.docx` (дані — з `config/report.toml`), а поля, шрифт (Times New Roman 14),
інтервал 1,5, абзац 1,27 см і стилі підписів узято з `Шаблон_бакалаврської_роботи.dotm`
(реалізація — `src/mllabs/reporting/templates/report.css`).

## Структура файлу

```markdown
---
topic: "Тема з методички (вже підставлена каркасом)"
purpose: "Мета з методички"
---

## 1. Постановка завдання
## 2. Опис проведеної роботи
## 3. Результати
## 4. Висновок
## 5. Список використаної літератури
```

Ці п'ять розділів другого рівня — із шаблону кафедри; не перейменовуй і не міняй порядок.
Усередині розділів 2 і 3 використовуй підрозділи `###` за пунктами завдання. Заголовок `#` не
вживай. «Тема» й «Мета» друкуються автоматично із шапки.

| Розділ | Зміст |
|---|---|
| 1. Постановка завдання | Завдання з `ASSIGNMENT.md`, стисло, списком. Без змін по суті. |
| 2. Опис проведеної роботи | Датасет і його обґрунтування; методи: що застосовано, чому саме це, з якими параметрами. Тут — рисунки й таблиці, що ілюструють хід роботи. |
| 3. Результати | Підсумкові таблиці й графіки, їх аналіз і порівняння. Усе, що завдання вимагає у розділі «Звіт повинен містити». |
| 4. Висновок | 1–3 абзаци: що зроблено, для чого, що це дало — з ключовими числами. Без нових фактів. |
| 5. Список літератури | Нумерований список реально використаних джерел (документація бібліотек, статті методів, джерело датасету). |

## Синтаксис (розширення Markdown)

**Рисунок** — окремим рядком; підпис і номер додаються автоматично («Рис. N. Підпис»):

```markdown
Розподіл цільової змінної показано на рис. {@target}.

![Розподіл класів цільової змінної](../artifacts/figures/target_distribution.png){#target}
```

Необов'язкова ширина: `{#target width=70%}`. Посилання в тексті (`рис. {@мітка}`) має стояти
**до** рисунка — така вимога шаблону.

**Таблиця з CSV** — той самий запис, але шлях до `.csv`; над таблицею з'явиться
«Таблиця N. Підпис» праворуч:

```markdown
Порівняння моделей наведено в табл. {@models}.

![Метрики моделей на тестовій вибірці](../artifacts/tables/model_comparison.csv){#models}
```

**Таблиця вручну** (для текстових, не числових даних) — рядок підпису перед Markdown-таблицею:

```markdown
Таблиця: Опис ознак датасету {#features}

| Ознака | Тип | Опис |
|--------|-----|------|
| age    | числова | вік клієнта |
```

**Число з результатів** — з `artifacts/metrics.json`, шлях через крапку, формат як у Python:

```markdown
Випадковий ліс досяг F1 = {{metrics.random_forest.f1:.3f}} проти {{metrics.baseline.f1:.3f}}.
```

**Формули** — LaTeX: у рядку `$F_1 = 2PR/(P+R)$`, окремим блоком `$$ ... $$`.

**Код** — у звіті лише короткі ключові фрагменти (до ~15 рядків) у блоках ```` ```python ````.

Шляхи — відносно `report.md`, тобто артефакти — це `../artifacts/...`. Неіснуючий файл, мітка
чи ключ метрики зупиняють збирання зі зрозумілою помилкою — це захист від розбіжностей із кодом.

## Правила змісту

- **Числа не переписуються руками.** У тексті — `{{metrics...}}`, у таблицях — CSV з артефактів.
  Якщо потрібного числа немає в `metrics.json` — його має додати код, а не автор звіту.
- **Кожен рисунок і таблиця — згадані в тексті** до своєї появи й **проаналізовані** після: що
  видно і який із цього висновок. Рисунок без коментаря — зайвий.
- **Обґрунтування вибору.** Завдання прямо вимагає пояснювати вибір методів: «обрано X, бо …;
  альтернатива Y гірша тут через …» — з опорою на властивості даних, показані в EDA.
- **Чесні висновки.** Якщо аугментація не допомогла або модель слабка — так і пишемо, з поясненням.
- **Обсяг:** орієнтир 8–15 сторінок; 6–12 рисунків. Краще менше рисунків, але кожен по суті;
  кілька однотипних графіків об'єднуй в один (сітка `subplots`) ще на рівні коду.

## Стиль

Академічний, безособовий («виконано», «побудовано», «отримано»), теперішній або минулий час.
Десятковий роздільник у тексті, що пишеш ти, — кома («0,85»); підставлені з метрик числа
лишаються з крапкою — це допустимо. Англомовні назви методів — як є (SMOTE, Isolation Forest),
при першому вжитку з українським поясненням. Без розмовних зворотів, без емодзі, без «ми».

## Збирання і перевірка

```bash
uv run mllabs report N
```

Потім **відкрий PDF** і переглянь кожну сторінку: рисунки чіткі й не обрізані; широкі таблиці
влізли (якщо ні — зменш кількість колонок або знаків після коми в коді, що їх зберігає);
заголовок не лишився внизу сторінки без тексту; нумерація рисунків і таблиць послідовна; на
титульній немає «???» (якщо є — поля `config/report.toml` не заповнено, повідом автора).
Проміжний HTML для налагодження: `labs/labNN/report/build/report.html`.
