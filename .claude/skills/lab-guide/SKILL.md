# Навчальний конспект GUIDE.md

**Читач:** досвідчений Java-інженер. Знає ООП, патерни, колекції, потоки, тестування. Не знає
синтаксису Python понад базовий, pandas/NumPy, статистики й машинного навчання.

**Мета:** прочитавши конспект, він може (а) пояснити викладачеві кожен крок лабораторної,
(б) знайти будь-який крок у коді, (в) змінити параметр і передбачити, що зміниться.

Це не звіт (він для викладача) і не переказ коду. Це розмова з колегою біля дошки.

## Структура

```markdown
# ЛР №N — <коротка людська назва>: конспект

## 1. Коротко
5–7 речень: яку задачу розв'язували, на яких даних, що отримали (з головними числами).

## 2. Навіщо це взагалі
Проблема простими словами, до будь-яких термінів. Що було б, якби цього не робити.
Місце цієї лабораторної в ланцюжку ЛР1→ЛР5.

## 3. Словник
Таблиця: термін (укр. + англ. оригінал) | пояснення одним-двома реченнями | аналогія з Java/буденна.
Лише терміни цієї лабораторної; уже пояснені раніше — посиланням на попередній GUIDE.

## 4. Як це зроблено — крок за кроком
Підрозділ на кожен `Step` із `lab.py`, у порядку виконання:
- **Що:** що робить крок.
- **Навіщо:** яку проблему знімає; що було б без нього.
- **Як:** ідея методу людською мовою (за потреби — маленький числовий приклад «на пальцях»),
  потім 5–15 рядків ключового коду з посиланням `src/mllabs/labs/labNN/файл.py:рядок`
  і розбором незнайомих конструкцій Python.
- **Що вийшло:** реальний результат — число, таблиця або графік (`![..](artifacts/figures/x.png)`)
  і як його читати («вісь X — ..., що вище крива — то ...»).
- **Чому саме цей метод:** альтернативи й чому обрано цей.

## 5. Python очима Java-розробника
Таблиця «у Java ти б написав → у Python тут написано» для конструкцій, що вперше трапилися
в цій лабораторній, із посиланнями на рядки коду.

## 6. Запусти й поекспериментуй
Команди запуску. 3–4 експерименти: «зміни X у `config.py` на Y → очікуй Z, бо ...».

## 7. Що може спитати викладач
6–10 запитань із короткими відповідями, включно з незручними («чому accuracy тут погана метрика?»).

## 8. Що почитати далі
3–5 конкретних джерел (розділ документації, стаття, відео) з позначкою, що саме там шукати.
```

## Правила викладу

- **Термін — після пояснення.** Спершу ідея словами, потім назва: «…частку правильно знайдених
  хворих серед усіх хворих — це називають *повнотою* (recall)».
- **Аналогії з Java — лише точні.** `Pipeline` ≈ ланцюжок `Function.andThen`; `fit/transform` ≈
  двофазна ініціалізація; `DataFrame` ≈ таблиця БД в пам'яті; `Protocol` ≈ interface. Якщо аналогія
  кульгає — скажи, де саме, або не вживай її.
- **Числа — справжні**, з `artifacts/metrics.json` і CSV; округлюй до 2–3 знаків. Графіки вставляй
  відносними шляхами від `labs/labNN/`.
- **Посилання на код — перевірені**: файл і рядок існують і містять саме те, про що мова.
- **Чесність.** Що не спрацювало, де результат слабкий, які є обмеження — окремими реченнями.
- Формули — лише коли без них гірше, і кожну розшифруй словами.
- Без води, без «у сучасному світі», без переказу методички. Обсяг — скільки треба, щоб пояснити
  (зазвичай 300–600 рядків Markdown).
- Мова — українська; англійські терміни в дужках при першому вжитку, далі — один варіант.
