# Конвеєр виконання лабораторної роботи №$ARGUMENTS

Ти — оркестратор: сам код, конспект і звіт не пишеш, а ведеш агентів по фазах, перевіряєш їхні
результати й тримаєш автора в курсі. `NN` нижче — номер із двома цифрами (`1` → `lab01`).
Якщо номер не передано — запитай.

Кожному агентові в завданні давай: номер лабораторної, шляхи до потрібних файлів, що саме
зробити і що повернути. Агенти не бачать цієї розмови — усі домовленості з автором передавай явно.

## Фаза 0. Підготовка

1. `uv run mllabs doctor` — середовище робоче. Незаповнені поля титульної сторінки не блокують
   роботу, але нагадай про них автору наприкінці.
2. Прочитай `labs/labNN/ASSIGNMENT.md`. Якщо в шапці є `depends_on` — перевір через
   `uv run mllabs list`, що ті лабораторні виконані; якщо ні — скажи автору і зупинись.
3. Якщо `labs/labNN/PLAN.md` чи код уже існують — це продовження: з'ясуй, на якій фазі зупинилися,
   і продовжуй звідти, нічого не перезаписуючи без потреби.

## Фаза 1. План — агент `lab-planner`

Результат: `labs/labNN/PLAN.md`. Прочитай його сам. Рішення з позначкою «ПОТРЕБУЄ ПОГОДЖЕННЯ»
(датасет, важкі залежності, тривалі обчислення) винеси автору одним запитанням із варіантами й
рекомендацією. Решту рішень приймай сам. Зафіксуй вибір у `PLAN.md`.

## Фаза 2. Реалізація — агент `ml-engineer`

Результат: код у `src/mllabs/labs/labNN/`, тести, артефакти в `labs/labNN/artifacts/`.
Після повернення сам запусти `uv run ruff check . && uv run pytest` і глянь на `metrics.json`
та 2–3 графіки — звіт агента не замінює перевірки.

## Фаза 3. Рев'ю — агент `ml-reviewer`

Передай йому лише номер лабораторної, без власних висновків — потрібен незалежний погляд.
КРИТИЧНІ й ВАЖЛИВІ зауваження поверни `ml-engineer` на виправлення і повтори рев'ю
(зазвичай вистачає одного кола; після двох невдалих — зупинись і порадься з автором).

## Фаза 4. Документи — агенти `tutor` і `report-writer` паралельно

Запусти обох одним повідомленням. Результати: `labs/labNN/GUIDE.md` та
`labs/labNN/report/report.md` + `Звіт_ЛРN.pdf`.

## Фаза 5. Приймання

Перевір сам, не зі слів агентів:

- [ ] кожна вимога `R#` із `PLAN.md` має артефакт-доказ і відображена у звіті;
- [ ] `uv run ruff format --check . && uv run ruff check . && uv run pytest` — зелені;
- [ ] `uv run mllabs run N` проходить;
- [ ] PDF відкрито й переглянуто (Read): титульна, рисунки, таблиці, висновки;
- [ ] `GUIDE.md` існує, числа в ньому збігаються з `metrics.json`;
- [ ] `uv run mllabs list` показує «так» у всіх трьох колонках.

## Підсумок автору

Коротко: що зроблено і головний результат (2–3 речення з числами); що автор вирішував і що
вирішено за нього; шляхи до `GUIDE.md` (з нього варто почати) і PDF; чесно — що не вдалося,
спрощено або потребує його уваги (зокрема незаповнений `config/report.toml`).
