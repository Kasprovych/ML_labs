# План лабораторної роботи №5

Критичний аналіз детектора аномалій з ЛР4 (EfficientNetB0 → ознаки патчів 32×32×512 →
**Feature Autoencoder** → карта помилки відновлення; VisA: `macaroni2`, `capsules`, `pcb4`):
математична інтерпретація ваг і латентного простору, пояснення Integrated Gradients і Grad-CAM,
перевірка адекватності пояснень (perturbation analysis, sanity checks), розбір FP/FN на
неоднорідному тлі, контрольований дрейф розподілу (освітлення, шум, розмиття, стиснення, зсув
камери) і межі придатності для edge-пристроїв реального часу (TFLite, квантування).
Нових залежностей немає: IG і Grad-CAM — через `tf.GradientTape`, TFLite — `tf.lite` з TF 2.21.

Перевірки, на які спирається план (2026-11-17, Apple M1 Pro, load average 3–13, проби на 1–2
зображеннях, 4 потоки TF). Цифри — орієнтири для інженера, **не** для звіту. **ЛР4 зараз переробляється** (регуляризація,
раннє зупинення, max_epochs ≈ 60) — обраний backbone, пороги, оцінки й кількості FP/FN нижче
зміняться; план від них не залежить (усе читається з артефактів ЛР4 під час `run 5`):

- `load_bundle(labs/lab04/artifacts/models/macaroni2)` відновлює детектор за ≈ 1 с; оцінка
  `000.JPG` = 1,31394 — **збігається** з `test_predictions.csv`. Шари наскрізної моделі:
  `image → feature_extractor → patch_aggregation_p1 → fae_head → postprocess`; усередині
  `feature_extractor`: `tile_split, preprocess, backbone, upsample, concat, channel_pooling,
  tile_merge`; `backbone` має два виходи `(32,32,240)` `block4a_expand_activation` і `(16,16,672)`
  `block6a_expand_activation`; `fae_head`: `normalization → fae_core → reconstruction_error`;
  `fae_core`: `input_noise, encoder_hidden, dropout, latent, decoder_hidden, reconstruction`.
- «Поетапний» прохід (виклик цих шарів по черзі в `GradientTape`) дає ту саму оцінку, що й
  `detector(x)` (до 1e-6). За повідомленням рев'ю ЛР4, `keras.Model(det.inputs, backbone.output)`
  падає (backbone вкладений двічі), тому ЛР4 додає `build_detector/load_bundle(...,
  expose_backbone=True)` з виходами `backbone_shallow` і `backbone_deep` — **основний API для
  Grad-CAM у ЛР5** (D4); поетапний прохід лишається запасним варіантом. Частка
  ненульових пікселів Grad-CAM: 36 % (шар кроку 8), **88 %** (шар кроку 16 — дифузна карта);
  HiResCAM (grad ⊙ activation): 31 % / 7 %.
- **Критично для IG:** класичні базові лінії для детектора аномалій **не нейтральні** — їх оцінка
  аномальності вища за саме аномальне зображення: чорне 2,25, середнє train 2,55, розмите (σ = 10)
  1,66 проти 1,31 у дефектного зображення (поріг 0,48; нормальні train 0,35–0,56). Тоді
  ΣIG = F(x) − F(b) < 0, і атрибуція пояснює «чим x *менш* аномальне за базу».
- Повнота IG (трапеції): розмита база — похибка 10 % при m = 32, 0,6 % при m = 128; середня —
  12 % / 1,7 %; найближче нормальне train-зображення (macaroni2) — 1–3 % при m = 64, але для
  capsules відносна похибка вибухає (2,4), коли F(x) − F(b) ≈ 0,02 (об'єкти в інших позиціях).
  Локалізація |IG| (AUROC проти маски) на одному зображенні: розмита/середня база ≈ 0,997–0,998;
  позитивна частина IG з найближчою нормою — 0,65–0,82. Вибір бази — емпіричний (D3).
- Час IG: m = 64 кроки (2 пакети по 33) ≈ 3,5–6,6 с на зображення при 4 потоках; m = 128 ≈ 6 с.
- TFLite у TF 2.21 (`tf.lite.TFLiteConverter`, `tf.lite.Interpreter` — працюють, але з
  попередженням про застарілість; пакета `ai_edge_litert` немає):
  - повна модель **не конвертується**: `AnomalyMapPostprocessing` використовує `[..., tf.newaxis]`

## 2. Ключові рішення

### D1. Що вважати «вагами» для інтерпретації і на яких даних

Модель — це ланцюг `f(x) = max · Blur·Up( e(z(x)) )`, де `x` — зображення, `φ(x)` ∈ R^{32×32×912} —
конкатенація двох шарів backbone, `F = φ·P` — фіксоване усереднення каналів до D = 512
(матриця `P`, `channel_pooling_matrix`), `z = (F − μ)/σ` — нормалізація з train, `ẑ = g(h(z))` —
FAE (кусково-лінійний: leaky ReLU), `e = (1/D)‖ẑ − z‖²` — помилка патча. Навчаються лише ваги FAE;
backbone і `P` фіксовані. Тому «інтерпретованість ваг» розкладається на чотири змістовні питання:

| Варіант (що аналізувати) | Математичний зміст | Плюси | Мінуси |
|---|---|---|---|
| 1. Внесок каналів і **шарів backbone** у помилку | `e = Σ_d e_d`, `e_d = (ẑ_d − z_d)²/D` — **точний** адитивний розклад; канал `d` = середнє вхідних каналів `S_d` із ваги `P[:,d]` → частка шару = Σ_d e_d · (вага каналів шару в `P[:,d]`) | точний, без апроксимацій; відповідає на «що бачить модель: текстуру (крок 8) чи контекст (крок 16)»; дешевий (кеш ознак) | канали backbone самі по собі не мають людської семантики |
| 2. **Спектри ваг** FAE і чутливість входів | SVD `W` кожного `Dense`, ефективний ранг `exp(H(σ²/Σσ²))`; ‖W_enc1[d,:]‖ — наскільки енкодер «слухає» канал `d` | буквально «аналіз ваг»; дешевий | спектр сам по собі мало каже про аномалії — потрібна зв'язка з (1) |
| 3. **Латентний простір** (k = 64) | коди `h(z)`; participation ratio `(Σλ)²/Σλ²` — скільки вимірів реально використано; Махаланобіс у латенті | показує, чи аномалія «поза многовидом» (велика помилка) чи «на многовиді, але рідкісна» (великий Махаланобіс) | PCA-2D — лише ілюстрація |
| 4. **Лінійні проекції**: PCA-k і локальний якобіан | PCA-64 = оптимальний **лінійний** автоенкодер; FAE локально афінний: `ẑ ≈ J z + b`, `J = ∂ẑ/∂z` має ранг ≤ 64; для «ідеального» проектора `J² = J`, сингулярні числа ≈ 1 (дотичні напрями) або ≈ 0 | найглибша математична інтерпретація: помилка = норма компоненти, ортогональної до вивченого многовиду; PCA дає повністю прозору еталонну модель | якобіан 512×512 на патч — лише на підвибірці (256 + 256 патчів) |

**Рекомендація: усі чотири, у звіті — в порядку 1 → 4** (від «що» до «чому»). Деталі:

- Дані: train — підвибірка 100 тис. векторів (seed) для PCA, латентних статистик, Махаланобіса;
  val (labelled) — для вибору top-k каналів і порогу «дефектного патча»; test — звітні числа.
- «Дефектний патч» на сітці 32×32: частка пікселів маски в патчі 8×8 ≥ 0,25 (`defect_patch_coverage`);
  «нормальний патч» — патчі нормальних зображень. Патчі аномальних зображень поза маскою — окрема
  група «контекст дефекту» (видно, чи помилка «розтікається»).
- Канал 512 → шар: для кожного вихідного каналу `d` частка шару 8 = Σ_{i<240} P[i,d] (решта — шар
  16); більшість каналів «чисті», змішаних 1–2 — розподіляються пропорційно (`LayerAttribution`).
- Карти «лише шар 8» / «лише шар 16»: `e^(l) = Σ_d e_d·w_{l,d}` → та сама пост-обробка → Pixel
  AUROC/AP на test. Це не перенавчання, а розклад тієї самої оцінки (сума двох карт = карта моделі
  до згладжування).
- Top-k каналів: відношення `R_d = E[e_d | дефект] / E[e_d | норма]` на **val**; крива «Pixel AUROC
  карти з top-k каналів» k ∈ {8, 16, 32, 64, 128, 512} — на test (порядок каналів із val).
- PCA-64: `fit` на нормалізованих train-векторах (`z`), залишок `‖z − U Uᵀ z‖²/D`; головні кути між
  span(U) і лівими сингулярними векторами останнього `Dense` (`reconstruction`, 256 → 512, top-64):
  `cos θ_i` = сингулярні числа `U_PCAᵀ U_dec`.
- Якобіан: `tf.GradientTape.batch_jacobian` ядра FAE на 256 нормальних і 256 дефектних патчах
  test (пакетами по 32); метрики: сингулярні числа, кількість σ_i > 0,5, «проекційність»
  `‖J² − J‖_F / ‖J‖_F`.

### D2. Дані для пояснень: які зображення і які частини розбиття

| Варіант | Плюси | Мінуси |
|---|---|---|
| 1. **Вибір налаштувань на labelled val, звітні числа на test** | test не впливає на жодне рішення (як у ЛР4); val вже розмічений | на val менше зображень для вибору (50 аномалій/кат.) |
| 2. Усе на test | більше даних | рішення під test — витік, заборонено |
| 3. Об'єднати val + test для FP/FN | більше помилок для статистики | пороги ЛР4 обрано на val → помилки val оптимістично занижені, групи неоднорідні |

**Рекомендація: варіант 1.** FP/FN — лише test (як `test_predictions.csv`); перерахунок val —
тільки для вибору бази IG, top-k каналів і перекалібрування порогів TFLite. Підвибірки для дорогих
методів (IG, perturbation) — детерміновані за seed: **15 аномальних зображень test на категорію,
стратифіковано за терцилями площі дефекту** (по 5) + усі FN (≤ 8) + 5 найвпевненіших FP (D7).
Дешеві методи (карта моделі, Grad-CAM, HiResCAM) — на **всіх** 50 аномаліях test.

### D3. Integrated Gradients: ціль, база, кроки — ПОТРЕБУЄ ПОГОДЖЕННЯ (база)

- **Ціль:** `image_score = max карти` — саме ця величина приймає рішення «аномалія/норма»; градієнт
  max проходить лише через окіл argmax (через гаусове ядро σ = 4 і рецептивне поле), тож IG
  пояснює **рішення**, а не всю карту. Альтернатива «сума `patch_scores`» (пояснює всю карту) —
  лише як опція `ig_target` (вимкнено), щоб не подвоювати час.
- **Інтегрування:** правило трапецій, `m = 64` кроки (пакети по 33), **перевірка аксіоми повноти**
  `ε = |ΣIG − (F(x) − F(b))| / max(|F(x) − F(b)|, τ)`, τ = 0,1·`threshold_image` (захист від ділення на
  ≈ 0, як у пробі capsules); якщо ε > 0,05 — повтор з m = 128, потім 256; записується фінальне m і ε.
- **Атрибуційна карта:** `A = Gauss_σ=4( Σ_c |IG_c| )` (модуль — бо знак залежить від бази, див.
  пробу) + окремо знакова сума для панелей. Згладжування тим самим σ, що й карта моделі, — щоб
  порівняння з маскою було на одній «роздільності»; сирі карти — на панелях.

| База `b` | Плюси | Мінуси (перевірено пробою) |
|---|---|---|
| Чорне зображення | стандарт Sundararajan et al. | дуже аномальне для детектора (2,25 > 1,31): F(b) ≫ F(x), атрибуція «від протилежного» |
| Розмите (σ = 10 пікс.) | зберігає освітлення й розташування; добра локалізація |в пробі|; найкраща збіжність | теж аномальне (1,66), Δ < 0 |
| Середнє train-зображення | «типова сцена» | найаномальніше (2,55); для capsules/macaroni2 об'єкти «розмазані» |
| **Найближче нормальне train** (L2 на 32×32 сірих, з 5 найближчих — з мінімальною оцінкою) | F(b) < порога → Δ > 0, ΣIG = «наскільки x аномальніше за схожу норму» — найчистіша семантика для детектора аномалій | несуміщені об'єкти (capsules) → атрибуція «різниці положень»; Δ може бути ≈ 0 для FN |
| **Expected Gradients** (Erion et al., 2021): K = 4 найближчі норми, m/K кроків на кожну | менша залежність від однієї бази | та сама проблема суміщення, трохи шумніше |

**Рекомендація:** рішення приймає **код на val**, а не автор: усі 5 баз на 5 аномальних
зображеннях val кожної категорії (75 IG, m = 64), критерій — середній піксельний AUROC `A` проти
маски за умови, що частка зображень з ε ≤ 0,05 ≥ 0,8; при різниці < 0,01 — простіша база (порядок
у `config`: розмита → найближча норма → EG → середня → чорна). Очікування за пробою: виграє розмита
або найближча норма. Обрана база фіксується в `metrics.xai.ig_baseline` і застосовується до test.
У звіті обов'язково — таблиця всіх баз з F(b): **нейтральної бази для детектора аномалій не
існує**, і це сам по собі висновок про межі IG. Погодження потрібне лише щодо підходу «вибір бази
кодом на val»; якщо автор хоче фіксовану базу — рекомендую найближчу норму (найкраща семантика).

### D4. Grad-CAM для backbone

- **Шари:** обидва джерела ознак — `block4a_expand_activation` (32×32×240, крок 8) і
  `block6a_expand_activation` (16×16×672, крок 16) з `DetectorConfig.layers`; глибші шари backbone
  на результат не впливають (обрізаний backbone), мілкіші — опція `gradcam_extra_layers` (порожньо).
- **Ціль:** той самий `image_score` (вищий = аномальніше, тому ReLU залишає «докази аномалії»).
- **Формули:** Grad-CAM: `α_c = mean_{ij} ∂S/∂A_c^{ij}`, `L = ReLU(Σ_c α_c A_c)`; HiResCAM (Draelos &
  Carin, 2020): `L = ReLU(Σ_c ∂S/∂A_c ⊙ A_c)` — для max-цілі градієнт локалізований, і GAP у
  Grad-CAM його «розмазує» (проба: 88 % ненульових на шарі 16), HiResCAM — вірний локальний варіант.
- **Злиття шарів:** білінійне збільшення до 256, нормування кожної карти на її max, середнє двох
  шарів (`fused`). Вибір «показувати шар 8 / шар 16 / fused» як основний — за AUROC проти маски на
  val (те саме правило, що в D3).
- **Реалізація:** `load_bundle(..., expose_backbone=True)` (API ЛР4, що додається на рев'ю) дає
  виходи `backbone_shallow`, `backbone_deep` поруч з `image_score`; у `tf.GradientTape` береться
  `tape.gradient(image_score, [backbone_shallow, backbone_deep])` (виклик моделі всередині стрічки,
  у власній `tf.function`, що повертає і активації, і градієнти). Тест обов'язково перевіряє, що
  градієнт не `None` і збігається з поетапним проходом. Якщо в Keras 3 градієнт за вихідним тензором
  виявиться `None` (вихід — не той самий тензор, що йде далі по графу), — запасний `StagedDetector`
  (3.1), який викликає шари по черзі з `tape.watch` активацій (перевірено пробою). Одна пара
  forward/backward на зображення — дешево, тож на всіх аномаліях test.

### D5. Кількісне порівняння карт (якість пояснень проти маски і карти моделі)

Для кожного аномального зображення і кожної карти (модель, IG, Grad-CAM-8/16/fused, HiResCAM,
випадкова — рівномірний шум як нижня межа):

- **Піксельний AUROC і AP** карти проти маски (у межах зображення);
- **Pointing game** (Zhang et al., 2018): argmax карти лежить у масці, розширеній на 8 пікс. (1 патч);
- **Частка маси в масці** `Σ_{mask} A⁺ / Σ A⁺` і її відношення до площі маски (> 1 — краще за випадкове);
- **IoU top-|маска|**: поріг за кількістю пікселів, рівною площі маски;
- **Spearman ρ** з картою моделі — «чи пояснення узгоджене з тим, що модель сама вважає аномалією».

Середні по зображеннях з 95 % бутстреп-ДІ (`BootstrapInterval` з `mllabs.modeling`, 1000 повторів,
seed); окремо за терцилями площі дефекту (дрібні дефекти — головна складність VisA).

### D6. Perturbation analysis — ПОТРЕБУЄ ПОГОДЖЕННЯ (спосіб «вилучення»)

Проблема: для детектора аномалій **будь-яке** штучне втручання (чорний квадрат, розмиття, шум) саме є
аномалією → видалення «доказу» може **підвищити** оцінку (проба: розмите зображення аномальніше за
дефектне). Тому:

| Спосіб «вилучення» патча | Плюси | Мінуси |
|---|---|---|
| Чорний / сірий квадрат | класика (Samek et al.) | гарантовано аномальний — криві беззмістовні |
| Розмиття патча | м'якше | у пробі розмиття підвищує оцінку |
| **Заміна вмістом еталонного нормального зображення** (найближча норма train, та сама позиція) | «вилучення» = «заміна на норму» — єдиний варіант, що залишає зображення в розподілі навчання (якщо об'єкти суміщені) | шви на межах патчів; для capsules — несуміщеність |
| **Гаусів шум σ = 32 у патчі** («зашумлення» за завданням) | буквально вимога завдання | сам створює аномалію — інтерпретувати лише відносно випадкового порядку |

**Рекомендація: обидва режими — «вилучення» заміною на норму (основний) і «зашумлення» (вимога)
— та метрика ABPC, стійка до цього артефакту.** Протокол:

- Сітка 32×32 (патч 8×8 — рідна одиниця моделі). Важливість патча = середнє карти пояснення в
  ньому. Кроки: k ∈ {0, 1, 2, 3, 5, 8, 12, 16, 24, 32, 48, 64, 96, 128} патчів (лог-шкала: дефекти —
  у медіані 0,05–0,9 % площі = 1–10 патчів); 14 станів зображення → один пакет.
- Порядки: карта моделі, IG, Grad-CAM-fused, HiResCAM, **маска-оракул** (патчі за покриттям маски
  — верхня межа), **5 випадкових** (середнє ± розкид) — нижня межа.
- **MoRF** (найважливіші першими) і **LeRF** (найменш важливі першими); відгуки — `image_score`
  і середня reconstruction error по всіх патчах та в зоні маски, нормовані на значення при k = 0.
- Метрики: AUC MoRF (менше — краще), **ABPC = Σ_k (f_LeRF − f_MoRF)/K** (Samek et al., 2017 —
  артефакт втручання однаковий в обох кривих і частково скорочується; більше — краще), ΔAUC проти
  випадкового; «інсерція» не потрібна окремо — LeRF + еталонна заміна дають той самий зміст.
- Зображення: 15 аномальних test/кат. (D2) + 5 найвпевненіших FP/кат. (для FP «правильне»
  пояснення має вказати на хибний доказ: його вилучення знімає тривогу).
- Обсяг: 20 зобр. × 3 кат. × (4 методи + оракул + 5 випадкових) × 2 режими × 2 напрямки
  (MoRF/LeRF; для випадкових — один) × 14 станів ≈ 25 тис. проходів (≈ 3–4 хв на 10 потоках).

### D7. FP / FN: вибір, групування, «фізичні причини»

- **Джерело:** FAE-рядки `labs/lab04/artifacts/tables/test_predictions.csv` (пороги ЛР4 з val).
  ЛР5 перераховує оцінки й звіряє (P3). PaDiM/PatchCore — лише для таблиці «чи помиляються інші
  методи на тих самих зображеннях» (перетин множин FP/FN; дешево — колонки вже є).
- **Чому test, а не val:** пороги обрано на val, тож помилки val систематично занижені і не
  репрезентативні; test — незалежна вибірка. Групи з n < `min_group_size` — лише описово. На момент
  планування FN було одиниці на категорію, а FP macaroni2 — більшість норм test (поріг близький до
  оцінок самих train-норм); після переробки ЛР4 це може змінитися — висновки звіту лише з
  `error_cases.csv`.
- **Дескриптори кожного зображення test** (розраховуються для всіх, не лише помилок):
  `brightness_std` (з ЛР4, σ яскравості на сітці 16×16), текстурна енергія (дисперсія лапласіана),
  середня яскравість, частка пересвічених (≥ 250) і тіньових (≤ 5) пікселів, **глобальна помилка**
  (медіана `patch_scores`) і **локальність** `max / median` (високий max при низькій медіані →
  локальна причина; висока медіана → глобальна: освітлення/текстура всього кадру); в околі argmax
  карти (вікно 24×24): сила країв (Собель), яскравість відносно медіани кадру, частка пересвіту,
  відстань до краю кадру (артефакти дзеркального доповнення); для аномалій — площа, **контраст
  дефекту** (|середня яскравість у масці − у кільці 8 пікс. навколо|), чи argmax у масці.
- **Крайові артефакти (відомо з рев'ю ЛР4):** на картах видно рамку вздовж країв і «гарячі кути»
  (FP macaroni2, pcb4) — імовірна структурна причина: доповнення (padding) згорток backbone змінює
  ознаки крайових патчів, а дзеркальне доповнення в пост-обробці підсилює кути. Окремий аналіз:
  (а) **середня карта аномалій нормальних зображень** (val + test норм) по категоріях — профіль
  «рамки»; (б) частка argmax FP у смузі ширини `border_px` і в кутових квадратах проти очікуваної
  частки за площею; (в) помилка патчів крайового кільця сітки 32×32 (1 і 2 патчі) проти центру на
  нормальних train (кеш ознак); (г) **діагностична пом'якшувальна міра**: оцінка зображення без
  крайової смуги b ∈ {0, 8, 16, 24} пікс. — Image AUROC/F1 з порогом, перекаліброваним **на val**,
  звіт на test (модель ЛР4 не змінюється; показує, скільки FP дає рамка; ризик пропуску дефектів біля
  краю — рахується, скільки масок test перетинають смугу). Причина FP «край кадру / кут» — у правилах нижче.
- **Порівняння груп:** FP ↔ TN (серед норм), FN ↔ TP (серед аномалій), по категоріях і разом;
  Манн–Вітні U, рангово-бісеріальна кореляція, поправка Голма на кількість дескрипторів; при n < 5
  у групі — лише описово (позначка в таблиці).
- **Причини (правила в `config`, прозорі):** FP — «глобальна текстура/освітлення» (медіана помилки >
  p90 медіан train-норм), «локальний відблиск» (пересвіт у вікні argmax > 5 %), «край об'єкта /
  структура» (сила країв у вікні > p90 норм), «край кадру / кут» (argmax ≤ `border_px` від одного / двох країв), інакше «не визначено»
  (правила перевіряються у фіксованому порядку з `config`);
  FN — «дрібний дефект» (площа < p25 площ аномалій test), «низький контраст» (< p25), «дефект поза
  картою» (argmax поза маскою, хоча піксельний AUROC зображення високий → проблема max-агрегації),
  інакше «не визначено». Таблиця частот причин + приклади. Правила — гіпотези, підтверджені
  дескрипторами; у звіті так і назвати.
- **Панелі:** до 6 FP і всіх FN (≤ 8) на категорію з найбільшою |score − threshold|/threshold:
  зображення з контуром маски, карта моделі з порогом, IG, Grad-CAM-fused, карта помилки шарів 8/16.

### D8. Дрейф розподілу (контрольовані зсуви)

Трансформації (детерміновані, seed; застосовуються до 256×256 `uint8` test; маски змінюються лише
для геометричних):

| Родина | Фізичний зміст | Рівні |
|---|---|---|
| Підсилення яскравості | інша експозиція / лампа | ×0,7, ×0,85, ×1,15, ×1,3 |
| Градієнт освітлення | нерівномірне освітлення, тінь | лінійний градієнт амплітуди 10 %, 20 %, 40 % |
| Гаусів шум | шум сенсора, мало світла | σ = 3, 6, 12 |
| Розмиття (Гаус) | розфокусування / рух | σ = 0,5, 1, 2 пікс. |
| JPEG (Pillow) | стиснення камери edge | якість 70, 40, 20 |
| Зсув кадру | вібрація, неточне позиціювання | 4, 8, 16 пікс. (`REFLECT`) |

Для кожної (категорія, родина, рівень): Image AUROC, Pixel AUROC, Pixel AP (з ДІ для чистих даних і
найсильнішого рівня — `ImageBootstrap` ЛР4), **FPR і TPR при порозі ЛР4**, медіанний зсув оцінки
норм, KS-статистика «норми під дрейфом vs чисті норми», pointing game карти моделі на аномаліях.
**Монітор дрейфу:** AUROC розрізнення «дрейф-норми vs чисті норми» за медіаною `patch_scores`
кадру (без міток!) — чи може edge-пристрій сам помітити дрейф. **Межа рівня** — перший рівень, на
якому Pixel AUROC падає більше ніж на `drift_auroc_tolerance = 0.02` або FPR зростає більше ніж на
`drift_fpr_tolerance = 0.10` (апріорні допуски). Обсяг: 19 рівнів + чистий × 3 кат. × ~100 зобр.
≈ 6 тис. проходів (≈ 1–2 хв).

### D9. Edge: що вимірювати і як оптимізувати — ПОТРЕБУЄ ПОГОДЖЕННЯ (TFLite)

| Варіант | Плюси | Мінуси |
|---|---|---|
| 1. **TFLite через `tf.lite` з TF 2.21** (без нових залежностей) | перевірено: fp32/fp16/динамічне int8/повне int8 конвертуються й запускаються (XNNPACK); дає реальні розмір, latency 1 потік, вплив квантування на якість | API застарілий (попередження; Google переносить у `ai_edge_litert`); повна модель не конвертується через `tf.newaxis` у пост-обробці → конвертується «backbone + FAE», пост-обробка (resize + blur, 0,009 GFLOPs) — окремо в TF |
| 2. `uv add ai-edge-litert` | майбутній офіційний інтерпретатор | нова залежність (небажана), не перевірено на macOS arm64 / Py 3.12 |
| 3. Лише аналітика з ЛР4 (GFLOPs, latency Keras) | без ризиків | не відповідає на «чи придатне для edge» — квантування і його вплив на якість невідомі |

**Рекомендація: варіант 1 + зведення ЛР4.** Деталі:

- Експорт: `keras.Model(detector.input, detector.output["patch_scores"])` → `export(format=
  "tf_saved_model")` у тимчасовий каталог → `TFLiteConverter.from_saved_model`; варіанти `fp32`,
  `fp16`, `dynamic_int8`, `full_int8` (калібрування: 64 train-норми, seed; вхід/вихід float32).
  Модель `.tflite` зберігається в `artifacts/models/<кат>/` (у `.gitignore`).
- Якість на test для кожного варіанта: Pixel AUROC/AP, Image AUROC, Image/Pixel F1 (а) за порогами ЛР4,
  (б) за порогами, перекаліброваними на val (квантування зсуває шкалу помилки — проба: max відхилення
  0,87 для повного int8); відхилення карт від Keras (max, Spearman ρ).
- Latency: `tf.lite.Interpreter(num_threads ∈ {1, всі})`, 5 прогрівів + 30 вимірювань, медіана/p90,
  batch 1 (реальний час); + пост-обробка окремо (Keras, 1 потік); load average фіксується.
- Роздільність входу 256 / 224 / 192 (FAE — MLP на патч, працює на будь-якій сітці; через
  `dataclasses.replace(config, image_size=…)`, `eval_size` = 256, тож маски ті самі): якість і
  latency fp32 — «дешевший кадр» як оптимізація.
- MobileNetV2: **не перенавчати** — рекомендації за таблицею `study_backbones.csv` ЛР4 (якість і
  latency backbone на macaroni2); перенавчання FAE на MobileNetV2
  для 3 категорій — опція `edge_train_mobilenet = False` (+ ≈ 4–5 хв, потребує ознак capsules/pcb4).
- **Межі придатності** (`limits_of_applicability.csv`): для кожного варіанта (backbone × точність ×
  роздільність): latency 1 потік ≤ 33 мс (30 FPS) / ≤ 100 мс (10 FPS), ΔPixel AUROC ≤ 0,01 до fp32,
  розмір; плюс межі дрейфу з D8 (який рівень освітлення/шуму/розмиття/зсуву допустимий) і висновки
  FP/FN (де метод непридатний, напр. macaroni2 на рівні зображення). M1 Pro ≠ edge-плата —
  у звіті: числа — відносні (співвідношення варіантів), абсолютні для ARM Cortex-A/Jetson не
  стверджуються; GFLOPs — апаратно-незалежна міра.

### 3.5. Тести (`tests/labs/test_lab05_*.py`, `tests/anomaly/test_staged.py`) — без мережі, малі моделі

- `expose_backbone=True`: `tape.gradient(image_score, [backbone_shallow, backbone_deep])` не `None`
  і збігається з градієнтом поетапного проходу (backbone `weights=None`, вхід 64×64) до 1e-5.
- IG: на `f(x) = Σ w·x²` аксіома повноти виконується до 1e-3 при m = 64; ескалація кроків
  спрацьовує, коли ε > допуску (підмінена функція); нульова атрибуція при `x = b`.
- Grad-CAM/HiResCAM: форма `(N,256,256)`, невід'ємність; на моделі, де ціль залежить лише від
  одного каналу в одній позиції, HiResCAM ненульовий лише там.
- `ErrorDecomposition`: Σ канальних внесків = помилка головки (до 1e-5); частки шарів у сумі = 1;
  `LayerAttribution` на `channel_pooling_matrix(912, 512)` — частка шару 8 для «чистих» каналів 0/1.
- `LinearProjectionBaseline`: на даних точно в k-вимірному підпросторі залишок ≈ 0.
- `LocalizationEvaluator`: ідеальна карта = маска → AUROC 1, pointing 1, IoU 1; рівномірний шум → AUROC ≈ 0,5.
- Perturbation: оракул на синтетиці (оцінка = сума «дефектних» патчів) дає монотонну MoRF і
  ABPC > випадкового; випадкові порядки відтворювані за seed.
- Трансформації дрейфу: форма і `uint8` збережені, рівень 0 = тотожність, `Translation` зсуває маску
  так само, детермінізм за seed.
- `TfliteExporter` на крихітній моделі: fp32-вихід ≈ Keras (1e-4); int8 конвертується.
- `CauseRules`: синтетичні дескриптори → очікувані мітки причин.
- `Lab4Handoff`: відсутній `detector.json` → зрозуміла помилка з порадою `mllabs run 4`.
- `Lab5` на мікро-фікстурі (2 синтетичні категорії, крихітний backbone з `weights=None`, підмінений
  `Lab4Handoff`) проходить усі кроки й пише очікувані ключі `metrics.json`.

## 5. Ризики та обмеження

### 5.1. Час обчислень (Apple M1 Pro, CPU, усі потоки, без навантаження; за пробами під load 3–13)

| Етап | Оцінка |
|---|---|
| 1. Завантаження 3 детекторів, зображень, перерахунок val/test (кеш ознак ЛР4) | 0,5–1 хв |
| 2. Ваги: розклад помилки, PCA-64 на 100 тис., латент, якобіан 512 патчів × 3 | 1–2 хв |
| 3. Вибір бази IG: 5 баз × 5 зобр. × 3 кат. = 75 IG (m = 64, частина з ескалацією) | 2,5–4 хв |
| 4. IG на test: ≈ 15 + FN + 6 FP ≈ 27 × 3 = 80 IG; Grad-CAM/HiResCAM на всіх аномаліях | 3–4 хв |
| 5. Perturbation ≈ 25 тис. проходів; рандомізація + стійкість ≈ 45 IG | 4–5 хв |
| 6. FP/FN: дескриптори, статистика, панелі | < 1 хв |
| 7. Дрейф ≈ 6 тис. проходів + метрики | 1–2 хв |
| 8. Edge: 4 варіанти × 3 кат. (конвертація ≈ 3–16 с кожна), оцінка test, latency, роздільність | 3–4 хв |
| 9. Зведення, графіки | < 1 хв |
| **Разом** | **≈ 17–25 хв** |

Під навантаженням (інженер ЛР4 запускає повторний прогін) — у 2–4 рази довше; фінальний `run 5`
(і latency!) запускати на вільній машині. Регулятори: `ig_anomalies_per_category` 15 → 10,
`ig_steps` 64 → 48 (ескалація однаково гарантує повноту), `val_images_for_selection` 5 → 3, вимкнути
`EXPECTED` і `BLACK` бази, `random_orders` 5 → 3, `edge_input_sizes` → `(256,)`, повне int8 лише для
macaroni2.

### 5.2. Залежність від ЛР4 (API може змінитися на рев'ю)

- ЛР5 покладається на: `load_bundle(directory, expose_backbone=True) -> (DetectorConfig,
  keras.Model)`; ключі виходів `anomaly_map`, `image_score`, `patch_scores`, `backbone_shallow`,
  `backbone_deep`; для розкладу помилки (D1) — імена шарів `feature_extractor`, `backbone`
  (2 виходи), `upsample`, `concat`, `channel_pooling`, `tile_merge`, `patch_aggregation_p{p}`,
  `fae_head` → `normalization`, `fae_core` (`encoder_hidden`, `latent`, `decoder_hidden`,
  `reconstruction`), `reconstruction_error`, `postprocess`; поля `DetectorConfig` (зокрема `layers`,
  `threshold_*`, `tile_grid = 1`); колонки `test_predictions.csv` і `method = "FAE"`; розміщення
  `labs/lab04/artifacts/{models,tables}/`; кеш `data/processed/visa/{splits.csv,images,features}`.
  **Пом'якшення:** усі звернення до імен — лише в `Lab4Handoff` (і `StagedDetector`, якщо знадобиться);
  тест «градієнти за виходами `expose_backbone` = поетапний прохід» ловить розбіжність.
- Числа ЛР4 (обраний backbone, пороги, latency, кількості FP/FN) після переробки зміняться — план не
  зашиває їх у код; `edge_lr4_summary.csv` копіює актуальні таблиці ЛР4 під час `run 5`; шари для
  Grad-CAM беруться з `DetectorConfig.layers`.
- `models/` у `.gitignore` → на чистому клоні спершу `mllabs run 4` (≈ 22 хв).
- Якщо на рев'ю ЛР4 зміниться обрана конфігурація (backbone, p, g) — ЛР5 працює без змін для
  g = 1; для g = 2 Grad-CAM/`StagedDetector` потребує доробки (тайли).
- Бажано (не обов'язково) у ЛР4 замінити `patch_maps[..., tf.newaxis]` на `tf.expand_dims(..., -1)`
  у `AnomalyMapPostprocessing` — тоді в TFLite конвертується і пост-обробка (не перевірено).

### 5.3. Методичні обмеження (назвати у звіті)

- Нейтральної бази IG для детектора аномалій немає (проба); атрибуції — відносно обраної бази.
- `image_score = max` → IG і Grad-CAM пояснюють лише найаномальнішу точку; FN, у яких дефект не
  дав максимуму, пояснення «не бачить» за побудовою.
- Perturbation-метрики залежать від способу вилучення (OOD-артефакти); ABPC і порівняння з
  випадковим/оракулом зменшують, але не усувають цей ефект.
- Мало FN (5/8/4 на test) → висновки про причини FN описові; FP macaroni2 переважають (поріг ЛР4 ≈
  рівень оцінок самих норм).
- `brightness_std` ЛР4 рахується по всьому кадру (об'єкти + тло), а не лише по тлу; «динамічне тло»
  в статичному VisA моделюється дрейфом (D8), а не відео.
- Дрейф — синтетичний; реальні зміни (інша партія виробів, пил на об'єктиві) можуть бути іншими.
- Latency — на M1 Pro через TFLite/XNNPACK; на ARM-платах абсолютні числа інші, переносяться лише
  співвідношення; `tf.lite` застарілий (попередження) — при майбутньому оновленні TF крок 8 має
  пропускатися з записом причини в `metrics.edge.skipped`.
- Розмір .tflite не дорівнює пікові RAM (тензорна арена не вимірюється) — зазначити.

### 5.4. Дані та залежності

- Нових Python-залежностей немає (TF/Keras 3, numpy, scipy, sklearn, Pillow — уже є).
- Датасет VisA — з кешу ЛР4 (`data/raw/visa/`, `data/processed/visa/`); мережа не потрібна.
- TFLite-експорт пише тимчасові SavedModel у `tempfile.TemporaryDirectory` (не в `artifacts/`).
