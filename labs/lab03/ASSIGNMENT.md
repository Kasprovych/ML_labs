# Лабораторна робота №3

**Етап розробки та навчання моделі**

## Завдання для виконання

### Етап 1. Підготовка даних та створення baseline-моделі

Обрати модель з Лабораторної роботи №2 (з високою кількістю гіперпараметрів або схильну до перенавчання, наприклад: Random Forest, XGBoost, Support Vector Machine, Gradient Boosting).

Зафіксувати метрику якості відповідно до типу задачі (наприклад, F1-score, ROC-AUC для класифікації або RMSE/MAE для регресії).

### Етап 2. Дослідження 1: Порівняння методів оптимізації (Grid vs. Random vs. Bayesian)

Визначити простір гіперпараметрів для обраної моделі (не менше 3–4 параметрів).

Провести оптимізацію трьома методами:

- Full Grid Search (GridSearchCV)
- Random Search (RandomizedSearchCV) з N={20,50} ітераціями
- Bayesian Optimization (використовуючи Optuna або BayesSearchCV) з N = 20 ітераціями

Зафіксувати час виконання кожної стратегії та найкраще значення валідаційної метрики.

### Етап 3. Дослідження 2: Оцінка впливу Data Leakage

Побудувати два експериментальних пайплайни:

- Некоректний пайплайн (з витоком)
- Коректний пайплайн (без витоку)

Порівняти отримані валідаційні метрики та оцінити величину штучного завищення якості.

### Етап 4. Дослідження 3: Оцінка незміщеної якості (Nested Cross-Validation)

Реалізувати схему вкладеної крос-валідації:

- Зовнішня петля: K=5 фолдів для оцінки узагальнювальної здатності.
- Внутрішня петля: K=3 фолди для підбору гіперпараметрів.

Порівняти тестову оцінку з внутрішньої CV та незміщену оцінку із зовнішньої CV у Nested CV.

## Вимоги до звіту та підсумкового аналізу

У звіті обов'язково мають бути присутні:

- Порівняльна таблиця методів оптимізації з колонками: «Метод оптимізації», «Кількість ітерацій / оцінок», «Час виконання (сек)», «Best Score (Inner CV)», «Unbiased Score (Nested CV)».
- Порівняння витоку даних: таблиця/графік різниці метрик для коректного та некоректного препроцесингу.
- Графік залежності «Якість моделі / Час обчислень».
- Висновки: обґрунтування доцільності вибору того чи іншого методу оптимізації для реальних задач із врахуванням обмежених обчислювальних ресурсів.
